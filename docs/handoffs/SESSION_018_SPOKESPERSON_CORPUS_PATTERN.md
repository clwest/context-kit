# Session 018 — spokesperson-corpus sub-pattern bundled

## Why this handoff exists

The 24/7 Global AI spokesperson corpus in
`unified-donkey-betz` was the first worked instance of a
generalizable pattern: a public-voice markdown corpus that
grounds a spokesperson AI (Character OS, chat widget, support
agent) in the project's source-of-truth. That project kept
its working spec at `docs/docs-pattern/spokesperson-corpus/`.

This session lifts the pattern up into the context-kit bundle
so every project generated by `context-kit init` (or refreshed
via `init --force`) gets it at
`docs/docs-pattern/spokesperson-corpus/` automatically. No more
manual `cp -r` between sibling projects.

## Why bundle the pattern now (vs. wait for the CLI)

The pattern's content (templates, recipe, voice guide) is the
load-bearing part. The CLI is convenience on top. Bundling the
content first means:

- Adopters can use the pattern today via `cp -r`.
- The shape gets stress-tested across more projects before the
  CLI API solidifies.
- `init --force` already refreshes the entire `_pattern/`
  bundle, so adopters get future pattern improvements for free.

## AI Notes

The spokesperson-corpus bundling decision is a recurring
pattern shape in context-kit: a generalizable artifact first
emerges in one downstream project, gets distilled, then gets
lifted into the bundle so every future `init` carries it. The
sub-pattern shape (folder under `cli/_pattern/` with its own
README/RECIPE/templates) is new — previous additions extended
the eight guide docs directly. The new shape is correct: the
guide docs are universal teaching material; sub-patterns are
optional composed patterns adopters pick up only when their
project has the matching surface (a public-facing spokesperson
in this case).

The proposal-without-implementation choice on the CLI side is
worth flagging. The temptation was to ship the CLI in the same
PR as the bundle. Resisting that keeps the API surface
provisional until a second worked instance proves the shape.
This matches the discipline that produced `handoff write`:
two stress-test projects (character-os SESSION 158 + this
repo) before locking the contract. One instance is data; two
is a pattern.
