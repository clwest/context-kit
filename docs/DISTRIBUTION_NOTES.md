## LinkedIn post — long-form follow-up

Posted 4 days after the original announcement. Names the people whose
feedback shaped the work; shows the receipts (commit SHAs).

> **Update on context-kit — what shipped from your feedback**
>
> A few days ago I posted about context-kit (the AI-collaboration
> scaffolding I distilled from ~1,100 sessions). The replies on that
> post turned into the next several commits.
>
> The shape of the tool is now three commands that work together:
>
> - `context-kit init` — creates the project memory structure
> - `context-kit seed idea.md` — turns a raw idea into Claude-ready
>   starting context
> - `context-kit orient` — loads the current context for the next AI
>   session (the bundled Claude skill calls this automatically)
>
> Three threads from the announce post, three real shipped features:
>
> **Damian Tedrow** — suggested an "orient tool" that *assembles*
> session-start context instead of being a static doc, and described
> a "hot path" file-size dashboard he uses to detect when an agent is
> outside its effective context. Both shipped:
> - `context-kit orient` (commit 5cf4a86)
> - `context-kit hotpath` (commit d1ed2d1)
>
> **Brian Turney** — pushed on "split context": the deeper failure
> isn't context loss, it's that docs / runtime / outputs drift apart
> over sessions. His ask was "a single authoritative path the system
> can't deviate from." That's now `orient` (the path) plus
> `inventory --check` (the gate that fails CI when narrative and
> runtime disagree):
> - `context-kit inventory` with --write/--check/--json (commit ae581fb)
>
> **Austin** — asked for a Claude skill: "give the skill file to my
> agent and it does everything." Shipped at
> `skills/context-kit/SKILL.md`, copied automatically into every
> generated project at `.claude/skills/context-kit/SKILL.md` (commit
> a1bb7cc).
>
> Bonus 1: `context-kit seed idea.md` turns a structured markdown
> idea file into the load-bearing project context — anchor doc TL;DR,
> first milestone in start-here, bootstrap handoff, build plan.
> Deterministic, no LLM. So an agent can start building with
> direction, not guess from an empty scaffold.
>
> Bonus 2: context-kit follows its own pattern. The repo's inventory
> is auto-generated by the tool, and `inventory --check` is wired up
> the way you'd wire it in your own CI.
>
> Install — `0.4.2` is on PyPI as of today. The package name is
> `contextkit-ai` (the unsuffixed `context-kit` was rejected as too
> similar to another project), but the CLI command is still
> `context-kit`:
>
> ```
> pip install contextkit-ai
> context-kit init "My App"
> cd my-app && $EDITOR idea.md
> context-kit seed idea.md
> claude
> ```
>
> Repo: https://github.com/clwest/context-kit
> Release notes: https://github.com/clwest/context-kit/releases/tag/v0.4.2
>
> Still on the punch list: real public users, real dogfood reports.
> If you try it and it breaks, the `[dogfood]` issue template is the
> fastest way to tell me.

>

>   the runtime-derived inventory disagrees with what code actually
>   ships in the same commit (commit ae581fb).
>
> So the structure isn't just slowing drift — there's a check that
> blocks the merge. Still rough around the edges (the inventory
> excludes itself from its own counts, learned that one the hard
> way), but the loop holds in CI now.

## What we deliberately are not doing here

- **Show HN.** The repo is at v0.4.2 with the wheel install live.
  Show HN is a swing once there's a couple of public dogfood
  reports under our belt — not before.
- Newsletter pitching. Same reason.
- A blog post on the technical design. The session handoffs in
  `docs/handoffs/` are essentially that, in working form.
- Asking people to "star" the repo. Stars don't help us learn what
  breaks.

The whole point of the launch sequence above is to convert the
~~232 impressions~~ + 12 comments on the original post into a
handful of actual users — not into a metrics screenshot.
