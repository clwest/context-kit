### Option D — Fix the `tests/` PATTERN_EXCLUDES gap

Pre-existing follow-up flagged in Session 1: `tests/` is not in
`PATTERN_EXCLUDES` in `cli/bootstrap.py`, which means generated
projects ship our test files inside `docs/docs-pattern/tests/`.
Harmless but noisy. Tiny fix:

```python
PATTERN_EXCLUDES = frozenset({
    "cli", "starter", "examples", "bin", "tests",   # add "tests"
    "__pycache__", ".git", ".pytest_cache", ".venv",
    "context_kit.py", "docs_pattern_bootstrap.py",
})
```

Plus a smoke test that confirms `docs/docs-pattern/tests/` is *not*
in a generated project.

### Option E — Wire `inventory --check` into CI

Now that `--check` exists and is CI-friendly, add a step to
`.github/workflows/` that runs it after the test suite. Failing
build = drift between code and inventory in the same commit. This is
the proof-of-concept that the drift verifier pattern actually
prevents drift in practice, not just in theory.
